## Story

As a **usuario**,
I want **pedirle al bot un export de mis datos de Firefly III (transacciones en un rango de fechas, o todo) y recibirlo como archivo descargable en el chat**,
so that **pueda hacer una copia propia de mis datos financieros sin entrar a la web**.

## Acceptance Criteria

<!-- LOCKED. -->

1. Un comando (ej. `/exportar` o `/exportar 2026-01-01 2026-03-31`) dispara la exportación de transacciones de Firefly III en el rango pedido (o todo, si no se especifica rango).
2. El resultado se entrega al usuario como archivo (CSV) adjunto en el chat (`sendDocument` de Telegram), no como texto en el mensaje.
3. Mientras la exportación está en curso (puede tardar si hay muchos datos), el bot avisa que está trabajando en vez de dejar al usuario esperando sin respuesta.
4. El archivo se genera y se entrega sin quedar persistido en disco del Bot Service más allá del tiempo necesario para el envío — se limpia después, exista éxito o error.
5. La operación usa el PAT del propio usuario — nunca expone datos de otro usuario ni usa un PAT ajeno.

<!-- Keep to ~3-7. -->

## Tasks / Subtasks

- [ ] Crear el cliente REST de exportación de datos de Firefly III (con soporte de rango de fechas opcional) (AC: #1, #5)
- [ ] Implementar el comando, incluyendo el mensaje de "trabajando en esto" para exports grandes (AC: #1, #3)
- [ ] Implementar el envío del archivo vía `sendDocument` y su limpieza posterior (AC: #2, #4)

## Testing

<!-- LOCKED. -->

- **Approach:** Unitario con el cliente REST de exportación mockeado y con `sendDocument` mockeado.
- **Key scenarios:** exportación de un rango de fechas; exportación sin rango (todo); archivo entregado correctamente vía `sendDocument`; archivo temporal limpiado tras el envío (éxito y error); archivo que excede el límite de tamaño de Telegram.
- **Per-AC verification:** AC #1 → cliente REST invocado con el rango correcto (o sin rango); AC #2 → `sendDocument` invocado, no `sendMessage` con el contenido; AC #3 → mensaje de "trabajando" enviado antes del resultado final si la operación tarda; AC #4 → verificación de que no queda ningún archivo temporal tras la ejecución; AC #5 → credenciales resueltas por `chat_id`, nunca un PAT ajeno.
- **Fixtures / mocks:** mock del cliente REST de exportación con datos de prueba (nunca datos reales); mock de `sendDocument`.
- **Edge cases to cover:** rango de fechas sin ninguna transacción (exportar un CSV vacío igual, no fallar); rango de fechas invertido (fecha final antes que la inicial, rechazar); archivo que supera el límite de Telegram.

# 8.5: Preparar entorno y cuentas sintéticas para la prueba de carga

**Story ID:** 8.5
**Epic:** 8 — Observabilidad y hardening

## Story

As an **administrador del sistema**,
I want **tener listos el script de prueba de carga, 50 cuentas Firefly III sintéticas con sus
PAT, plantillas de mensajes realistas, y un plan de limpieza**,
so that **8.6 pueda ejecutar la prueba de carga de 50 usuarios concurrentes sin arriesgar datos
ni cuentas reales**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Existe un script/herramienta de prueba de carga (ej. k6, Artillery, o equivalente) capaz de
   simular 50 usuarios virtuales concurrentes enviando mensajes al Bot Service de forma
   sostenida, incluyendo al menos un escenario de ráfaga (varios usuarios virtuales escribiendo
   dentro de la misma ventana de segundos). El script se valida primero con una corrida piloto de
   2-3 usuarios virtuales antes de darse por listo para 50.
2. Existen 50 cuentas Firefly III sintéticas dedicadas exclusivamente a la prueba, cada una con su
   propio PAT generado vía el flujo de alta de usuarios de Epic 1 (o un script de setup
   equivalente si el flujo automatizado de 1.2/1.3 aún no cubre el caso), corriendo en un entorno
   equivalente a producción (mismo docker-compose, mismo dimensionamiento de VPS) pero claramente
   delimitado para no contaminar datos financieros reales.
3. Existen plantillas de mensajes en lenguaje natural variados (registro de gasto y consulta),
   distribuibles entre los 50 usuarios virtuales, para que la carga generada no sea
   artificialmente uniforme.
4. Existe un script/plan de limpieza documentado y probado que purga las 50 cuentas y datos
   sintéticos, listo para ejecutarse después de que 8.6 corra la prueba.

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. NEVER run tests or quote coverage here. -->

- **Approach:** validación del script de carga contra un volumen bajo (piloto de 2-3 usuarios
  virtuales) antes de considerarlo listo para 50; verificación manual de que las 50 cuentas
  sintéticas existen, tienen PAT válido, y están claramente marcadas como no-reales.
- **Key scenarios:** corrida piloto del script con 2-3 usuarios; verificación de que el script de
  limpieza efectivamente elimina/purga una cuenta de prueba sin afectar cuentas reales.
- **Per-AC verification:** AC #1 → la corrida piloto completa sin errores y genera al menos un
  mensaje del escenario de ráfaga; AC #2 → las 50 cuentas responden a una llamada simple de la API
  de Firefly III con su PAT respectivo; AC #3 → revisión manual de que las plantillas cubren
  variedad de montos/categorías/fraseo, no un único mensaje repetido; AC #4 → ejecutar el script
  de limpieza contra 1-2 cuentas de prueba y confirmar que quedan eliminadas/purgadas.
- **Fixtures / mocks:** ninguno — esta historia crea las fixtures reales (cuentas sintéticas) que
  8.6 usará.
- **Edge cases to cover:** qué pasa si el flujo de alta de usuarios de Epic 1 aún no está
  automatizado (1.2/1.3) — el AC #2 permite un script de setup equivalente como fallback
  explícito.
